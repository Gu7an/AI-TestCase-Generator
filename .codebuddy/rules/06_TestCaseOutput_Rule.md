# Test Case Output Rule

## Internal Analysis Order

内部分析必须完成以下十段并按顺序检查（不得跳过）。

其中仅第五段「测试用例」与第十段「冒烟测试用例」进入最终交付物；
交付范围以 `00_OutputFormat_Rule.md` 为准（唯一真源），其余八段不展示。

```text
一、需求分析摘要

二、功能拆解

三、业务规则

四、测试场景矩阵

五、测试用例

六、需求覆盖检查

七、遗漏补充

八、重复/无效用例处理

九、需求待确认

十、冒烟测试用例
```

# Coverage Report

内部质量检查记录（必须完成，但不进入交付物、不展示）：

```text
需求覆盖：
X/X

业务规则覆盖：
X/X

正常场景：
X

异常场景：
X（按 04_TestCaseQuality_Rule 第 2.1 节判定标准统计，不含业务规则拦截）

业务规则场景：
X（单独统计，不得与异常场景混计）

依赖覆盖：
X/X（对照 01_RequirementAnalysis_Rule 第 8 节依赖清单）

状态转换覆盖：
X/X（对照 01_RequirementAnalysis_Rule 第 5 节生命周期状态机）

领域清单覆盖：
X/X（对照 07_DomainRiskChecklist_Rule）

边界场景：
X

数据场景：
X

状态场景：
X

权限场景：
X

网络场景：
X

兼容性场景：
X

历史回归：
X
```

禁止在未完成维度判定的情况下输出覆盖率数字。

禁止手填覆盖率细分数字。

所有维度数量必须由用例数据实测得出，并满足：

```text
各维度之和 = 用例总数（或明确标注维度可重叠）
细分之和 ≤ 总数 + 说明
```

若出现「手填 65 条、实测 42 条」这类自相矛盾，判定为覆盖率报告无效。

# Output Principles

最终输出必须：

```text
准确
完整
可执行
可验证
可追溯
无明显重复
```

不要为了展示AI分析过程输出大量无关内容。

最终交付物一律为 `.xlsx` Excel 文档，且只交付「测试用例」与「冒烟测试用例」两部分。

交付范围、载体、Sheet 结构、命名与保存位置，
一律引用 `00_OutputFormat_Rule.md`（唯一真源）；本文件只规定内部十段分析与表格内容口径。

对话回复只给简短摘要与文件路径，禁止粘贴用例表正文、规则矩阵与覆盖率报告。
