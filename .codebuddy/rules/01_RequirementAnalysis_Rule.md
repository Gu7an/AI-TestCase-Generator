# Requirement Analysis Rule

## Objective

将自然语言需求转换为结构化测试模型。

禁止直接根据需求段落逐句生成测试用例。

---

# 1. Requirement Scope

必须识别：

- 需求目标
- 功能范围
- 非功能范围
- 用户角色
- 功能入口
- 前置条件
- 操作流程
- 输入
- 输出
- 业务规则
- 状态
- 数据
- 权限
- 异常处理
- 外部依赖
- 上下游影响
- 兼容性
- 回归范围

# 3. Functional Decomposition

将功能拆解为最小可测试单元。

示例：

```text
订单管理
├── 创建订单
├── 查询订单
├── 修改订单
├── 取消订单
└── 支付订单
```

每个功能必须进一步识别：

```text
正常
异常
边界
数据
状态
权限
网络
重复
并发
依赖
兼容
回归
```

不适用的维度必须标记：

```text
N/A
原因：当前需求不涉及该维度
```

---

# 4. Business Rule Decomposition

业务规则必须转换为：

```text
条件 → 操作 → 结果
```

例如：

```text
条件：订单状态=待支付
操作：用户发起支付
结果：订单进入支付处理中
```

继续分析：

- 正常条件
- 条件不满足
- 边界条件
- 非法条件
- 状态不允许
- 重复操作
- 操作失败
- 重试
- 中断
- 恢复

---

# 5. State Analysis

必须识别需求中所有业务对象的生命周期状态机。

范围包括但不限于：

- 数据库/接口中的状态字段（订单状态、支付状态等）
- 业务对象的生命周期状态（订阅、报告生成、任务、审核流等）
- 前端交互状态（页面加载中、提交中、生成中、刷新中）

禁止只分析显式的「状态字段」而忽略业务对象的生命周期。

输出格式：

```text
对象：订阅
  未订阅 --点击购买--> 支付中 --支付成功--> 已订阅
                        |--支付失败/取消--> 未订阅
                        |--进程被杀/来电中断--> 支付中(待恢复)
  已订阅 --到期日自动续费--> 续费中 --扣款成功--> 已订阅
                              |--扣款失败--> 续费失败
  已订阅 --系统设置取消--> 已取消续费 --到达原到期日--> 已过期
  已过期 --权益回收--> 未订阅
```

必须逐项检查：

- 合法转换
- 非法转换
- 重复转换
- 跳跃转换
- 并发转换
- 失败转换
- 中断转换（进程被杀、来电、切后台、网络中断）
- 恢复转换
- 到期/过期转换
- 每个「进行中」状态被中断后的最终状态

强制要求：

```text
每个「进行中」状态（支付中、生成中、上传中）必须有对应的中断用例
每个「已失效/不存在」对象必须有对应的访问用例
```

---

# 6. Data Analysis

仅针对需求中真实存在的数据字段分析：

- 正常值
- 空值
- null
- 默认值
- 最小值
- 最大值
- 临界值
- 超范围
- 非法格式
- 特殊字符
- 超长
- 重复
- 不存在
- 删除
- 过期
- 历史数据
- 新旧数据

禁止对需求不存在的字段进行臆测。

---

# 7. Permission Analysis

分析：

- 未登录
- 普通用户
- 目标角色
- 管理员
- 无权限
- 权限过期
- 权限变化

同时判断：

```text
前端是否限制
API是否限制
数据是否隔离
```

---

# 8. Dependency Analysis

识别：

- API
- 数据库
- Redis/缓存
- MQ
- 第三方服务
- 文件服务
- 登录服务
- 支付服务
- 推送服务
- AI/算法服务
- 系统能力（相机、麦克风、相册、定位、通知）
- 上游模块
- 下游模块

重要依赖必须分析：

```text
正常
失败
超时
异常返回（错误码、脏数据、字段缺失、空结果）
不可用（服务宕机、商品拉取失败、票据校验失败）
重复回调 / 重复通知
中断（进程被杀、来电、切后台）
恢复
重试
```

必须输出依赖清单，并在进入场景分析前完成：

| 依赖 | 类型 | 调用时机 | 失败模式 | 对应用例ID | 已覆盖 |
|---|---|---|---|---|---|
| AI 分析服务 | 第三方 | 每日8点生成动态 | 失败/超时/返回空 | STR_020/021 | Y |
| App Store 内购 | 第三方 | 点击购买 | 失败/取消/重复回调/票据校验失败 | SUB_010/013/023 | Y |
| 系统麦克风 | 系统能力 | 点击话筒 | 权限被拒绝 | EDT_051 | Y |

规则：

```text
未填写「对应用例ID」的依赖视为未覆盖，必须在场景分析阶段补充
该清单需在 04_TestCaseQuality_Rule 中复核
```

计费类依赖（支付、AI 按次计费、短信）额外检查：

- 重复调用是否重复计费
- 失败是否误扣费
- 掉单后能否恢复
