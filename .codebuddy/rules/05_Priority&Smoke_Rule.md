# Priority & Smoke Rule

## Priority Principle

优先级基于：

```text
业务重要性
+
失败影响
+
风险等级
+
数据风险
+
用户影响
+
回归风险
```

禁止简单按照：

```text
正常=P0
异常=P1
边界=P2
```

进行分类。

---

# P0

P0 = 核心业务 + 高风险。

包括：

- 核心主流程
- 核心数据
- 核心状态
- 核心权限
- 核心接口
- 核心第三方依赖
- 严重历史缺陷
- 数据错误风险
- 核心业务不可用
- 失败会阻止发布

判断标准：

```text
该场景失败是否可能阻止发布？
```

如果是：

```text
优先考虑P0
```

---

# P1

P1 = 重要功能和重要风险。

包括：

- 重要业务规则
- 重要异常
- 边界
- 权限异常
- 数据兼容
- 网络异常
- 重要回归
- 上下游影响

---

# P2

P2 = 低风险、低频、非核心。

包括：

- 次要功能
- 低频异常
- 非核心兼容
- 非核心体验
- 优化类验证

---

# P0 占比控制

P0 必须收敛，否则失去筛选意义。

控制目标：

```text
P0 占用例总数的 20% ~ 35%
```

超过 40% 必须复核并重排。

禁止定为 P0 的类型（即使属于核心功能，也应降为 P1）：

- 静态展示类（图标、文案、slogan、静态元素）
- 排版、布局、颜色、动效
- 排序规则（列表顺序、模块顺序）
- 页面跳转与入口
- 纯展示的状态文案
- 边界值（除非边界涉及资损或数据安全）
- 次要权益的生效验证（主权益已覆盖时）
- 重复操作类（除非重复导致扣款或计费）

必须定为 P0 的类型：

- 资损（支付失败、掉单、重复扣款、误扣费）
- 数据安全（账号数据隔离、数据丢失、越权访问）
- 安全校验（凭证过期/重放/篡改、签名校验）
- 核心业务不可用（核心流程中断、核心依赖失败）
- 核心主流程（用户达成产品核心价值的必经路径）

复核方式：

```text
逐条询问：该场景失败是否会阻止发布？
答案为「否」的，降为 P1
```

---

# Smoke

冒烟测试原则：

```text
只从P0中选择
```

冒烟测试失败：

```text
阻止构建/发布
```

---

# Smoke Coverage

至少覆盖：

```text
核心功能
+
核心业务流程
+
核心接口
+
核心数据
+
关键状态
+
关键权限
+
核心回归
```

如果多个P0步骤属于同一个核心流程：

```text
允许合并为一个冒烟流程
```

---

# Smoke Validation

每条冒烟用例必须回答：

```text
失败是否应该阻止发布？
```

如果答案是：

```text
否
```

重新评估P0等级。

P0 名单发生变动后，冒烟清单必须同步重选，禁止沿用旧清单。
